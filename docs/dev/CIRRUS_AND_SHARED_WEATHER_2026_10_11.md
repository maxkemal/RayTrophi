## Implemented source increment

### Wider, developing flashes and gradient-only cirrus

Latest user feedback rejected the remaining leaf-like cirrus and narrow, mostly
vertical bolts. The latest captured frame is `cirrus_live_after_wisps_2026_10_11.jpg`.
At inspection cirrus was at 14000 m with .3 coverage/.3 opacity; an additional
liquid anvil occupied 9500..12500 m. Layers were not toggled, so screen position
alone does not identify which of those fields creates a particular thin patch.

Cirrus no longer uses cellular RGB channels for either coverage or filaments.
Coverage/bending use the base texture's gradient alpha; detail alpha now receives
an independent signed-gradient FBM during noise generation. Liquid-cloud detail
keeps its RGB channels. Per-pixel cirrus remains two reads, with no periodic ribs
or cell envelopes. The new noise alpha needs fresh GPU noise textures: rebuild
cloud_noise along with all cloud consumers and restart the application normally.
Existing noise resources in an already-running process are not regenerated by
changing source/SPV files on disk. This visual result is not yet accepted.

### Superseded first cirrus increment

Cirrus now uses finite-support, seeded feather packets in
`cloud_cirrus_shape.glsl`, called by the existing `cloudCirrus` transport.
Neighbouring packets vary their length, width, yaw, spine curvature and fibre
spacing. A broad head narrows toward its tail; fine texture breaks up oblique
filaments. High coverage gradually introduces a thin irregular veil.
Nine neighbouring cells use arithmetic only; the existing two texture reads
remain in `cloudCirrus`. Compact support fits the enumerated neighbourhood.
This removes the old global packet threshold as the principal shape generator.

Existing coverage, scale, direction, optical depth, weather seed and evolution
remain the authoring surface. UI, Python `rt.world.set_clouds(cirrus={...})`
and external IPC `world.set_clouds` use existing CloudState validation. No new
fields, packet layout, bindings or C++ authoring operations were added.
Vulkan RT production/reference and RayFusion consume the same implementation.
The model remains a single-scattering thin shell, with the existing assumption
that cirrus is behind liquid cloud layers. It does not add vertical ice volume.

Static checks cover the lookup budget, finite-support neighbourhood and consumer
wiring. They do not prove compilation, visual realism, distant filament aliasing
or GPU speed. Arithmetic includes nine packet hashes and local rotations.
Performance must be measured; unchanged texture count is not unchanged cost.

## Shared fast weather

World's existing WeatherParams remains authoritative. UI, Python and IPC commit
through `rtapi::setWeatherEffects`; invalid types, ranges and non-finite values
fail without committing. Climate still owns wind. Save/load and existing weather
keyframes retain their original storage.
The existing distant rain/snow curtain is also called from reference transport;
it remains the same bounded approximation, not a new reference random walk.

`weather_fast.glsl` runs on RT camera rays and the RayFusion HDR scene pass,
before common aerial/fog. Three near depth layers (2.5/8/22 m), world-space
wind/fall advection and different layer hashes replace the single angular layer.
Layers behind a primary hit are rejected; dust/mist use soft varying patches.
Weather stays outside RayFusion's sky history. The old miss weather tint is
removed so the sky does not receive two weather washes.
VulkanWeatherClock.cpp gives both Vulkan roles the same dedicated weather time:
timeline during playback/frozen evaluation, wall time for unpaused realtime
weather preview. This does not change the water/material clock. Airborne weather
wakes RayFusion presentation even when its camera is stationary.

`weather_surface.glsl` shares mesh/terrain wetness, snow/dust albedo/roughness,
slope support, sheltered settling and shading height between RT and RayFusion.
Exposure breakup uses the same procedural noise in both. Surface Only hides the
airborne effect while preserving cover; cover survives zero airborne intensity.
Weather wakes the shared frame with cloud layers disabled, also in colour/HDRI
worlds, without enabling liquid clouds outside Nishita.

This is bounded visual weather, not a particle simulation. There is no enclosure
query, splash collision, persistent deposit map or snow geometry. Large interiors
can contain the overlay. Dedicated SDF/volume/hair shaders do not acquire mesh
deposition here. The existing perspective-camera restriction of the RayFusion
cloud pass also applies to weather. CPU/OptiX keep their legacy rendering.

## Natural cloud shafts

The six existing sun samples are stratified within their existing segments to
reduce fixed quadrature bands. No extra noise reads or separate shaft march is
introduced. Sun direction, cloud altitude and gaps still drive natural shafts.
The old extra RT god-ray pass is skipped while effective liquid clouds render;
its controls show an explanation and are disabled for the Vulkan renderer then.
Legacy shafts remain available without liquid clouds and in other renderers.

Correction to the initial audit: `raygen.rgen` DOES contain
`computePrimaryGodRays`; missing usage in `miss.rmiss` was not evidence of a
missing Vulkan implementation. No new air/fog shaft integration was added.

## Lightning

The World/Atmosphere panel exposes these controls under **Weather > Lightning /
Storm flashes**. The World-cloud object properties retain the same controls.
This replaces the hard-to-find first placement below Cloud material. The Weather
panel commits only the lightning patch through the existing setCloudsJson service;
it does not reset other cloud controls. Timeline Play drives lightning, while
Realtime Weather Preview only drives airborne weather. Use 30..60 flashes/min
temporarily when framing the effect; the default 6/min is sparse and short flashes
can lie outside the camera or be rejected in clear regions. This UI move requires
a C++ rebuild; no shader change is involved in this placement correction.

CloudState now owns `lightning`: enabled, derive_rate_from_climate,
rate_per_minute, intensity, RGB color, center_m (X/Z footprint), extent_m,
ground_altitude_m, ground_strike_fraction, bolt_radius_m, duration_s,
horizontal_span_m and branching. Older projects default
to disabled. Climate-derived rate uses the existing DerivedWeather rate and is
read-only in the UI. Cloud serialization and keyframe interpolation include these
fields; flags remain discrete like existing cloud flags.

`CloudLightningParams.h` derives up to four events from timeline time and weather
seed in a fixed authored footprint. Four staggered lanes retain an event through
its duration. Requested rate accepts 0..600/min; the effective scheduling rate is
min(requested_rate, 160/duration_s), preserving long pulses under the four-event
budget. UI and get_clouds.lightning_effective_rate_per_minute expose that same
core calculation; it is an upper scheduling rate, not a visible-flash measurement.
An enabled convective layer (type >= .6),
positive coverage/extinction is required; the shader rejects clear portions of
the weather map. Cloud-ground and cloud-internal events share timing and records.
Internal events now travel primarily horizontally over horizontal_span_m (size
varies .65..1.35), with only a small altitude variation. Larger spans persist
longer through the same size factor. Defaults for new data use 15% ground strikes;
explicit saved ground fractions are preserved.

`cloud_lightning.glsl` adds local cloud radiance at EXISTING density events in
RT production/reference/RayFusion. Weather-map activity is cached once per ray.
Visible bolts have 24 growing trunk segments and up to four two-segment branches,
a bounding-sphere reject
and primary-depth occlusion. Only live visible bolts pay up to four cheap density
samples per crossed cloud interval for cloud occlusion. There are no mesh/TLAS
updates, created scene lights or new random walks. Ground altitude is authored,
not terrain collision. Dynamic lightning illumination of surfaces is not added.
RayFusion now accumulates stable cloud radiance only and composites transient
flash radiance from the same march outside that history. Transient event packets
are excluded from the stable history key. Frequent flashes no longer reset the
whole sky's convergence, and ended flashes cannot remain in that cloud history.
There are no extra march samples, history buffers or render passes for this split.
The leader opens progressively during the first 45% of its life; branches start
after their attachment node is reached and then extend in two stages. Branching
0 disables the branches. Cloud glow follows the developed span instead of only
the source point. No geometry, lights or extra volume marcher is created.

## Script and IPC

```python
rt.world.set_weather_effects(
    enabled=True, type=2, intensity=0.7, density=0.65,
    surface_accumulation_output=0.8, surface_height_output=0.4)
effects = rt.world.get_weather_effects()
rt.world.set_clouds(lightning={
    "enabled": True, "rate_per_minute": 180.0,
    "duration_s": 0.8, "horizontal_span_m": 16000.0,
    "branching": 0.85, "ground_strike_fraction": 0.1,
    "center_m": [0.0, 0.0, 0.0], "extent_m": 12000.0})
```

IPC uses `world.set_weather_effects` with `patch={...}`, `world.get_weather_effects`
and existing `world.set_clouds` with `lightning={...}`. New weather methods have
local registry descriptors with Read/SceneWrite permissions. Existing
`world.get_weather` remains climate-derived weather, not effect controls.
Invalid lightning values/RGB/centre arrays fail existing CloudState validation.
Lightning ranges: rate 0..600/min, intensity 0..10000, extent 100..200000 m,
ground altitude -500..20000 m, ground fraction 0..1, radius .1..30 m,
duration .08..3 s, horizontal span 100..50000 m, branching 0..1,
RGB 0..1 and finite centre components within +/-1000000 m. Unknown lightning
fields are rejected. Weather strengths are 0..1, scale .1..10, type integer 0..4,
visual_mode integer 0/1, enabled/surface_response_enabled boolean.
Final-render scene locks apply to weather and cloud edits; wind is read-only.
